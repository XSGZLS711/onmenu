# OnMenu 点单原型

面向斐济单店试点的可操作演示。使用六道模拟菜品，菜名保持中英双语，界面随浏览器语言选择中文或英文，可手动切换。

## 体验流程

1. 顾客点单：选择菜品、辣度、份数和备注。使用“邀请同桌”的相同链接或二维码可跨设备共享购物车。
2. 任意顾客提交本轮订单后，购物车锁定，等待前台确认付款。
3. 前台收银：接收扫码订单，也可以为柜台顾客新建订单。模拟现金收款与找零，或使用不重复的 M-PAiSA 示例交易号确认到账。
4. 收款确认同时创建厨房票据，清空原购物车并进入下一轮；已付款菜品保留在订单历史。
5. 厨房出单：显示全部已收款菜品，支持模拟补打、开始制作和标记出餐。
6. 店长管理：处理收银员发起的退款，查看模拟净收款和操作记录。待审核退款暂时阻止继续制作。

访问根路径会创建一个独立演示空间，地址栏中的 `room` 参数标识该空间；共享链接必须包含相同参数。每个演示最多 200 张订单。所有数据都保存在 D1，语言偏好仅保存在本机。

## 当前边界

- 所有菜品、照片、价格、收款、退款和打印均为演示，不可直接用于营业。
- 无 M-PAiSA 自动到账确认、人民币支付或实体小票机连接。
- 角色切换用于体验流程，不是身份认证。接口检查演示角色，但客户端可以切换角色，不能作为正式权限系统。
- Sites 预览为账号所有者私密访问；手机访问也需要该账号。实际顾客免登录入口、员工登录和桌码权限隔离需在正式版实现。
- 共用链接约每 1.8 秒同步。订单状态使用数据库版本条件更新，防止并发覆盖；金额由服务端模拟菜单计算。
- 下单前校验购物车版本；付款后递增轮次，拒绝旧轮次请求。网络不明确时显示错误并重新同步，不假定付款或加菜成功。
- 统计仅覆盖当前演示空间。营业日结、底钱、现金盘点、真实退款到账、对账与五店管理尚未实现。
- 食材、过敏原及正式售价待真实菜单确认。
- 注册了可选 WebMCP 读取和加菜工具。当前浏览器未提供支持的验证上下文，未验证该工具接口；普通点单流程不依赖它。

## 开发

依赖 Node >=22.13。业务模型测试使用支持原生 TypeScript 类型剥离的 Node 版本（本次使用 Node 25）。

```sh
npm install
WRANGLER_LOG_PATH=.wrangler/logs npx wrangler d1 execute DB --local --config wrangler.local.json --file=drizzle/0000_bitter_silver_surfer.sql
npm run dev -- --host 0.0.0.0
```

本地迁移只应初始化一次。已有表时不要重跑该 CREATE TABLE；后续变更使用追加迁移。`wrangler.local.json` 仅描述本地数据库，生产资源由 Sites 配置。

```sh
node --test tests/order-model.test.mjs
node tests/api-flow.mjs
npx tsc --noEmit
npm run build
```

API 测试要求本地开发服务正在运行，并会创建独立、可丢弃的测试空间。可用 `ONMENU_TEST_ORIGIN` 指定测试服务地址。验证包括多人加菜、重复提交、并发付款、找零、轮次重置、退款审核与持久化读回。

## 实现

- `app/page.tsx`：四个演示工作界面与双语交互。
- `lib/order-model.ts`：模拟菜单、金额计算、订单状态和业务规则。
- `app/api/demo/route.ts`：D1 读写与乐观并发控制。
- `db/schema.ts` / `drizzle/`：演示数据库结构和迁移。
- `public/food/`：为此次原型生成的食物示例照片。

当前开发端未进行浏览器交互或视觉测试；完成了业务模型、真实 HTTP 并发流程、TypeScript 和生产构建验证。
